## Findings

### The timing metrics were checked for vacuity before being believed

A median peak error of 0.0 is exactly the shape of number that can be true and empty. If both series peaked on the session's own day every time, the metric would report perfect agreement no matter what the model did.

They do not. Peaks land across the whole six-day window — 54 sessions at day 0, 41 at day 3, the rest spread — because a second session inside the window moves them. The engine gets the peak exactly right on 96 of 130 sessions for local fatigue and is genuinely wrong on the others, with errors from −4 to +5 days.

A test now requires the peak-error distribution to take more than three distinct values, so the metric fails loudly if the data ever becomes shaped in a way that makes it free.

### Timing needs no scale alignment, which makes it a stronger measure

A peak is an index; a crossing is a fraction of a series' own peak. Neither depends on the fitted scale, so unlike RMSE these metrics carry no nuisance parameter. Where a metric can be made independent of a fitted quantity it should be, and it is worth stating which ones are and are not.

### The recovery multiplier, measured

Checkpoint 2 left ρ's clipping as an open question. It is now a reported number: **clipped on 11.9% of days, longest run 7 consecutive days.**

That is one day in eight where the multiplier carries no information about *how* favourable the context is, only that it is beyond what the engine will express. The inverse-crime audit predicts clipping — true recovery propensity spans [0.68, 1.28] against the engine's [0.80, 1.15] — so this is the engine correctly declining to extrapolate rather than a defect. Whether the bounds are too tight is a question about what the clipped days cost, which needs the performance side; it moves to L3.3.

---

## Decisions

**High-load sessions are chosen from the observable log**, by working-set count, never from latent load. Which sessions count as heavy must not itself be a judgement made with the answers in hand.

**Per-muscle RMSE is not reported.** It would need sixteen fitted scales, one per muscle, and sixteen nuisance parameters fitted on the same data being scored would flatter the result. Correlation and directional accuracy need no scale, so per muscle those are what is reported.
