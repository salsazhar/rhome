**Layer:** L1 — Simulator
**Date:** 22 August 2026

## Purpose

Make the dataset imperfect on purpose, so the engine is forced to cope with gaps rather than assuming complete records.

One property matters more than the rates, and `DATA.md` §17 states it directly: **missingness must not be concentrated only in adverse scenarios.**

## Why the concentration property matters

If gaps clustered on bad days — the ring left off while ill, the scale skipped during a hard week — then **absence of data would itself carry information about the athlete's state.** An engine could learn to read a missing night as a warning sign.

That signal would be an artefact of the generator. It would score well on this dataset and fail on real data, where a ring goes uncharged for reasons that have nothing to do with training. Worse, it would fail in the direction that looks like success: the engine would appear to detect illness it was actually detecting a charging habit.

Measured across four seeds:

| | Rate |
|---|---|
| Ordinary days | 5.4% |
| Adverse scenarios (illness, sleep restriction, sleep compression, failure blocks) | 6.0% |
| Travel | 7.8% |
| **Share of all gaps falling on ordinary days** | **63%** |

The mild travel association is kept deliberately — people genuinely are less consistent away from home — and a test caps the multiplier below 3.0 so it cannot grow into a signal.

## Findings

### Bodyweight exercises were being given negative loads

A test asserting the generated data is clean caught `ab_wheel_rollout` recorded at **−5 kg**.

The cause: for a `reps_only` exercise, external load is derived by subtracting body mass from the target effective load. Where the athlete's own bodyweight already exceeds what the target calls for, the subtraction goes negative.

Negative external load is meaningful — it is assistance — but only for the assisted kinds. There is no such thing as a negatively loaded ab wheel rollout. The correct behaviour is no added load at all, with the athlete performing fewer repetitions instead, which the repetition model already handled.

External load is now clamped by exercise kind: free for `assisted_reps`, at least zero for `reps_only`, at least one increment for everything else.

This is a good example of a defect that no distribution check would have found. Every aggregate looked right; a single row was physically impossible.

### The test that caught it was itself slightly wrong

Having fixed the negative loads, the same test still failed, because it asserted every load is strictly positive. A bodyweight movement with no added weight legitimately records zero. The assertion now branches on exercise kind, which is the distinction it was reaching for.

---

## Decisions

**Steps survive a night the ring was not worn.** They come from the phone, not the ring, so they are excluded from the missable fields. Blanking them alongside HRV would imply a device relationship that does not exist.

**Body-mass gaps come in blocks, not scattered days.** Someone who stops weighing themselves stops for a stretch. Scattered single days would be trivially recoverable by interpolation, which is not the problem real data poses. A test requires at least one multi-day gap.

**A partial night loses exactly one metric, and not always the same one.** A test requires at least four of the five fields to be affected across a run, so the engine cannot special-case a single always-present channel.

**The dirty fixture distinguishes rejection from repair.** Sixteen malformed rows, each labelled with whether a correct parser should refuse it or fix it: a negative load is unrecoverable, whereas contradictory RPE and RIR fields, or a whitespace-padded categorical, have exactly one sensible reading. That distinction is the point of the fixture, and it is what L2.1 will be tested against.
