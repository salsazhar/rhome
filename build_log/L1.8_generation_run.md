## Reproducibility

The generated data stays out of version control: it is rebuildable from the seed and `generation_config.json`, which records every simulator constant, the athlete's sampled parameters, the scenario schedule and the commit hash.

What *is* committed is the **checksum manifest**. Without it, "evaluated against dataset 0.1.0" would be an unverifiable claim — the same seed on different code produces different data, and nothing would catch the difference. A test regenerates from scratch and requires byte-identical output; another edits a written file and requires the mismatch to be detected.

## Findings

### Drop-set loads bypassed the increment rounding

A test requiring every load to sit on a real equipment increment caught a machine drop set at 37.5 kg where the increment is 5 kg. Drop segments computed their load as a plain 75% of the previous set, without rounding.

Stripping plates lands on real increments like any other load change. This is the second defect in two stages that no distribution check would have found — an aggregate over 10,000 sets is unmoved by a handful of impossible values.

### CSV line endings were an unexamined default

The tamper-detection test failed at a surprising point: the tamper *was* caught, but restoring the original content did not restore the checksum. `csv.writer` defaults to `\r\n`, and reading then rewriting as text silently normalised it.

The test was fixed to work in bytes, but the underlying default was worth changing too. These files are opened by people in text editors as well as by pandas, and a line terminator that varies by platform is a poor property for an artefact whose checksum is part of its identity. Now set explicitly.

### A test predated the feature it was measuring

`test_body_mass_and_effort_are_sometimes_absent` measured the rate of sets without an effort rating, and began failing at 26% once warm-ups existed — because warm-ups deliberately carry no rating. The test was written when every set was a working set.

Not a defect, but worth recording: tests written against an earlier data shape can silently change meaning when the shape grows. This one failed loudly, which is the good case.

## Decisions

**Back-offs are identified per prescription, not per exercise.** A first attempt classed any set lighter than the day's heaviest as a back-off, which caught within-prescription load reductions and put back-offs at 29% of all sets. A back-off is a separate, deliberately lighter prescription; grouping by set-number resets identifies them correctly, and the share fell to 5.6%.

**Anchors follow a per-exercise schedule, not a global rotation.** The first version required a specific exercise on a specific day and produced four anchors in two years against a documented 60–120. Each anchor exercise now carries its own interval and fires when it is next trained in a low-fatigue state.

**Anchors are refused when systemic fatigue is high.** An anchor taken while fatigued carries no more information than an ordinary set while claiming, through its heavier weight in the engine's capacity update, to carry more.

**Warm-ups are stored with no effort rating.** They contribute no dose, and recording an effort for them would invite an engine to use them.
