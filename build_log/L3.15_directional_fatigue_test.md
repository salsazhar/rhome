# L3.15 — Does the per-muscle fatigue number predict anything?

**Date:** 26 August 2026
**Status:** ⛔ **the test design is void** — it scores chance on synthetic data
where the model is known to be nearly correct. What survives is a
signal-to-noise measurement, and that is the finding.
**Tool:** `tools/directional_fatigue_test.py` · **Report:** `directional_fatigue.txt`
**Data:** the 99 historical sessions (development data, D22). The Rhome-logged
sessions from 25 August were **not read**.

## The question

The engine holds a fatigue value per muscle and nothing had ever checked it
against anything observable. On synthetic data there is ground truth because we
wrote it; on a real log fatigue is latent and the number floats free.

**The test.** Within one session, take two exercises loading different primary
muscles. Before any set is seen the engine freezes a predicted suppression for
each. Does the one it calls *more* suppressed come in lower against its own
recent history?

Paired within a session so sleep, illness and week cancel. Direction rather
than magnitude because direction has a floor — chance is 50%. The observed side
never touches the engine's capacity estimate, so LIM-31 cannot contaminate it.

## The raw result

| predictor | | |
|---|---:|---:|
| **engine suppression** | **71/143 = 49.7%** | p = 1.0000 |
| engine, local term only | 62/143 = 43.4% | p = 0.1320 |
| session position | 61/143 = 42.7% | p = 0.0941 |
| decayed set count | 78/143 = 54.5% | p = 0.3156 |
| chance | 50.0% | — |

The instrument was verified before anything was concluded from that: a
predictor fed the answer scores 143/143, its inverse 0/143.

## The synthetic control, which voids the test

The identical design was run on synthetic data, where the engine reconstructs
the simulator's latent local fatigue at **+0.941 cross-sectionally** (between
muscles within a day, day means removed) and **+0.965 longitudinally**.

| | n | score | ceiling for a perfect model of this size |
|---|---:|---:|---:|
| synthetic | 4228 | **49.0%** | 54.6% |
| real | 143 | 49.7% | 50.6% |

At n = 4228 a true 54.6% sits about 6 SE from chance and would be plainly
visible. **The design fails to detect a model known to be nearly right.** The
real-data null is therefore void as evidence about the fatigue model, and two
successive readings of it — first "the model fails", then "the effect is too
faint to test" — were both premature.

Reproduced by `tools/directional_fatigue_control.py`.

## Why the effect size still matters — the check that changed the conclusion

The obvious reading is "the fatigue model is wrong". That reading is not
supported, and the check that shows it is the one that should have run first.

Ask instead: **what would a perfect model of the size the engine predicts have
scored here?** If observed = effect + independent noise, then

```
P(sign agrees) = 1/2 + arctan(σ_effect / σ_noise) / π
```

| | |
|---|---:|
| sd of predicted pair gap | **0.0060** |
| sd of observed pair gap | **0.3243** |
| ratio | **0.0184** |
| **score of a perfect predictor at this size** | **50.6%** |
| distance from chance at n = 143 | 0.14 SE — **not detectable** |

The engine scored 49.7%. A flawless model would have scored 50.6%. **This test
cannot distinguish them.** The null is therefore uninformative about whether
the engine's muscle ordering is right or wrong, and must not be quoted as
having refuted it.

An earlier draft of this entry did quote it that way. That was the same D19
failure the project keeps finding: an available explanation accepted because
the number pointed toward it.

## What the test DOES establish

The effect size, and it is decisive on its own.

| | |
|---|---:|
| median predicted suppression gap within a pair | **0.0032** |
| median observed residual gap within a pair | **0.179** |
| pairs with a predicted gap above 1% | **10 of 143** |
| predicted-to-observed sd ratio | **1.8%** |
| enlargement needed for a perfect model to reach 60% here | **18×** |

The engine's within-session muscle contrast is roughly **1.8% of the variation
actually present**. Whatever its direction, a signal this faint cannot drive a
readiness display: the number would be swamped by ordinary day-to-day variation
in every session it was shown.

## Where the contrast is lost

The underlying state is *not* flat. Across the sixteen muscles at training
time, local fatigue spans a median of **0.748** (max 1.586). The compression
happens downstream of the state, and three places were measured:

**1. The performance-weight vector is diffuse.** `local_exposure` is a weighted
*average* over the fatigue vector, normalised to unit sum, and it includes
secondary (0.5) and stabiliser (0.2) muscles.

| across the 54 exercises the athlete performs | |
|---|---:|
| muscles in the weight vector | median **6**, max 8 |
| share of weight on the primary muscles | median **0.556**, min 0.385 |

A barbell bench press puts **0.385** on chest. So a median 44% of any
exercise's exposure comes from muscles it does not target, and pairs with
disjoint primary movers still share a median **0.190** of their weight.

**2. λ_local = 0.065** scales the averaged exposure down again. Median local
term 0.0110; median total suppression **0.0240**, maximum ever reached on this
athlete **0.0475** — against a `suppression_clip` of 0.25 that is never
approached.

**3. All sixteen muscles share one half-life.** `MODEL.tex` §576 specifies
"$h_m$ is a muscle-specific half-life" and Table §1261 gives "24–42 h, mean
30 h". The implementation reads a single scalar `local_half_life_h = 30.0` in
`state.py:99` and applies it to every muscle in the loop. The mean of the
specified range is used for all sixteen, so nothing distinguishes muscles by
recovery rate — only by dose received and time elapsed.

That last one is a **specification/implementation divergence**, not a tuning
choice, and it is recorded as [LIM-37].

## Not fixable by scaling — still true, and now more precisely

```
local_A − local_B = λ_local × (exposure_A − exposure_B)
```

The sign is invariant to any positive λ_local, so **directional accuracy cannot
be changed by scaling**. But note what this now means: raising λ_local would
raise the effect size — and therefore the detectability — without altering a
single call. Size and direction are separable levers here, and only size has
been measured.

## Deliberately not concluded

The 0.005 effect-size floor gives 60.5% on 43 pairs and collapses to 40.0% on
10 pairs at 0.010. A real signal strengthens as the floor rises; this peaks and
collapses. It is noise and is not reported as anything else.

**Session position at 42.7%** — later exercises came in *better* — has a
plausible explanation: the reference is per exercise, so an exercise always
performed fourth already carries its position in its own history. Hypothesis,
not a check.

## The finding that survives

Same design, both datasets:

| | sd predicted | sd observed | ratio | ceiling |
|---|---:|---:|---:|---:|
| synthetic (Athlete A) | 0.0096 | 0.0668 | **14.4%** | 54.6% |
| real (this athlete) | 0.0060 | 0.3243 | **1.8%** | 50.6% |

Observed performance noise is **4.9× larger** on the real athlete; predicted
contrast is **1.6× smaller**; net the fatigue signal is **7.8× weaker relative
to noise** in reality than in the simulator.

That is a statement about the *simulator's realism*, not only about the engine,
and it may be the most consequential number this stage produced: every synthetic
criterion has been calibrated in conditions markedly quieter than reality.

## Consequence

**The readiness readout is not built** — on grounds of effect size, not of a
refuted direction. Not because the number is proven wrong, but because it is
proven faint: displaying "lats 61%" would mean displaying a quantity whose
predicted spread is 1.8% of the spread of what actually happens.

**The direction question remains open and needs a better-powered test.** This
design cannot answer it. A test that could would compare muscles with a *large*
true contrast — one trained within 24 h against one untrained for five days —
where the effect is not swamped. That is the natural next measurement, and it
can be built on the same 99 sessions.

Recorded as [LIM-36], revised.

## Addendum — a data-provenance confound, raised by the athlete

Oura history starts 316 days before training was logged. The gap itself is
harmless (fatigue decays to zero in under two weeks and stays there), but
`novelty_for` is keyed to the engine's own exposure memory, which starts at
day 0 of whatever calendar it is given — so every exercise's first *logged*
appearance was scored as this athlete's first-ever exposure to it, despite
years of prior training history the log does not capture.

Measured (`tools/novelty_seeding_check.py`): **42.4%** of the 976 real working
sets carry a materially inflated novelty multiplier, **55** get the full 25%
"never done this before" inflation, and the effect is concentrated early
(mean novelty 1.090 in the first 200 sets vs 1.049 in the last 200). Capacity
and `adaptation` are unaffected — checked directly. Recorded as [LIM-38] and
folded into the external diagnostic as Note 0 / H6, since it sits inside
exactly the data L3.15 analyses.
