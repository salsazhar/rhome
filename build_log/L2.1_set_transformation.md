# L2.1 — Input normalisation and set transformation

**Layer:** L2 — Inference engine
**Date:** 23 August 2026
**Status:** ✅ Passed
**Tests:** 524 total (69 added this stage)

## Purpose

The first engine stage. Read what a real application could collect, and turn each logged set into the four dose channels: adaptive stimulus per muscle, local fatigue per muscle, neuromuscular strain, and systemic load.

Keeping the four separate is the product's central modelling claim. More work raises both stimulus and fatigue, but not proportionally.

## Validation

**Golden values, hand-computed from the specification and asserted to nine decimal places.** An equation transcribed slightly wrong still produces plausible numbers, so "looks about right" is not a test. The back squat case is written out in full in the test docstring, including the Nuzzo interpolation, so the derivation is checkable without running anything.

**The model's central claim is asserted as the shape of two curves**, not as a coefficient: between 2 and 0 repetitions in reserve, stimulus rises 18% and fatigue 35%. Failure costing more than it buys is structural, and the test would fail if either table were flattened.

**Set-type inclusion**: warm-ups carry nothing; drop segments carry identical dose to a working set and are excluded only from performance estimation. A set outside the evidence's intensity domain also keeps its full dose — the work was performed — and loses only its performance eligibility.

**All sixteen malformed fixture rows are handled as specified**, and every rejection states a reason.

## Findings

### The parser rejected 29 rows of clean data

The first run of the parser against the generated dataset rejected 29 sets. All were RPE 2 or 3, refused by a floor of RPE 4 that I had chosen on the reasoning that a set easier than that is not a working effort.

That reasoning was mine, not the specification's. `MODEL.tex` §From RPE to RIR clips logged repetitions in reserve to [0, 8], which puts the corresponding RPE range at [2, 10]. My floor was narrower than the documented range, so the parser was discarding data the specification explicitly permits.

The bound is now **derived** from the documented reserve range rather than written as a literal, and a test asserts the relationship holds. The general failure is worth naming: a validation bound invented by intuition, sitting next to a specification that already defines the range.

The same run needed a fixture row changed — "RPE below the scale minimum" used 2.0, which is legitimate, and is now 1.0.

### Two fixture rows were not decidable by a parser

Building the parser showed that two of the sixteen malformed rows written at L1.7 could not be judged from the row itself: a load recorded in pounds, and twenty repetitions at a near-maximal load. Both are real failure modes, and neither is decidable without the athlete's history — a 220 kg bench press is implausible for this athlete and unremarkable for a world-class one.

Contextual plausibility belongs where capacity is known. Putting it in a parser would have meant the parser making claims it cannot support, so both rows were replaced with defects detectable from the row alone, and the reason is recorded in the fixture.

### My hand arithmetic was wrong, and the golden value caught it

The neuromuscular golden value failed on first run at a difference of 5 × 10⁻⁶. The code was right; I had rounded the relative intensity to 0.8534 before squaring it rather than carrying 0.853393665.

This is the ordinary way round for a golden value to fail, and it is the argument for computing them by hand in the first place: the discrepancy was far too small to notice by eye and would have been invisible in any tolerance loose enough to accommodate a rounding slip.

## Decisions

**Rejection and repair are distinguished, and neither guesses.** A defect is unrecoverable and the row is refused with a stated reason; a repair has exactly one sensible reading and is recorded. Silently coercing a bad row is how a parser turns a data-entry error into a physiological claim.

**Contradicting RPE and RIR resolve to RIR**, per `DATA.md` §5.3, which makes it the primary field.

**Engine parameters live in `rhome_engine`**, per D4, and are verified against the sections of `MODEL.tex` they cite by the existing Guardrail 3 machinery.
