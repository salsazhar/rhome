## Purpose

Estimate what a set implies about capacity, hold a slow underlying trend, and project performance forward under current fatigue — with the ordering that prevents target leakage enforced structurally rather than by discipline.

The build plan calls this the most delicate stage in the project. Leakage is the reason: it breaks nothing, produces no error, and simply makes every performance metric better than it should be.

## Guardrail 2: the ordering, made impossible to violate

Three quantities are easy to confuse and must not be: **observed performance** (what a set implies now), **estimated capacity** (the slow trend), and **projected performance** (capacity reduced by current fatigue). Only the third can be scored, because only it is a claim about something not yet seen.

The protection is structural, not procedural:

- A projection is **content-addressed**. Its digest covers the capacity, the projected value, the suppression and every fatigue term. Altering any of them invalidates it.
- **Re-freezing a session raises.** A second freeze is a recomputation, which is the leak itself.
- **Scoring without a frozen projection raises.** A residual measured against a prediction made after the fact measures nothing.
- **A tampered projection is detected on use**, not merely on inspection.

Each is demonstrated by attempting the violation. The central test seals a projection, ingests a session deliberately far from it, and asserts the sealed value and its digest are both unchanged.

## Behaviour that follows from the specification

**One anomalous session moves capacity by under 1%.** Scenario S11 requires this: a conspicuously bad day must not rewrite the estimate. The Huber clip bounds any single set's influence.

**Thirty consistent sessions do move it.** Bounded influence must not mean frozen, or genuine progress would never register. The clip bounds magnitude while preserving sign, so a run of same-signed residuals accumulates.

**An identical result is read more kindly when the athlete was tired.** The fatigue acting at the time is removed before the observation updates capacity, so a hard training block does not read as detraining.

**Capacity initialises from a median, not a mean**, which resists an early outlier — a test feeds 100, 250, 110 and requires 110.

## Findings

### A test that failed on a coincidence

The body-mass smoothing test asserted the smoothed value differs from the latest reading. It failed because the seven values I chose happened to have a median equal to the final one.

The code was right; the test was checking an incidental fact rather than the property it meant. Rewritten to test the property directly: a single heavy reading — a large meal the night before — must move the estimate by less than 250 grams, where taking the latest value would move it by more than a kilogram.

Worth noting because it is the third test this layer whose premise was wrong while the code was right. Tests written to assert a *consequence* rather than the *property* keep failing for reasons that have nothing to do with the system.

---

## Decisions

**Body mass is never imputed.** A bodyweight-involving exercise with no body mass on record yields no performance observation at all, rather than a guess from population statistics. The set still carries its full dose.

**The frozen record stores the fatigue breakdown, not just the number.** The explanation trace at L2.6 needs to say *why* a projection was what it was, and reconstructing that after the fact would mean recomputing it — the thing this stage exists to prevent.

**Capacity is corrected for fatigue before updating, and the residual is not.** The residual is scored against the frozen projection exactly as it stood; the correction applies only to what the observation implies about the underlying trend. Conflating the two would let the fatigue model quietly flatter its own predictions.
